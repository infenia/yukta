# Input requests (a plugin asks, the broker waits)

Reference for `InputBroker`, `InputRequestStore` and friends. Epic #1787; contracts in `plugin-api` (`com.infenia.yukta.plugin.input`), decisions in `design/decisions/0001-input-requests.md`.

- **Gateway**: `DefaultInputGateway` is a singleton bean; a plugin takes `InputGateway` through an `ObjectProvider`. `ask` reads run and node from the Reactor context (`InputIdentity.from`), so the engine binds identity and a plugin never passes an execution or node id.
- **Broker**: `ask` (resume from `findAnsweredByKey`, join an open request with the same key, caps, redact, `createIfAbsent`), `answer`, `escalate`, `cancel`, `cancelExecution`, `sweep`. Every change is `transition`: read, check the allowed state and version, `compareAndSet`, re-read on a lost race. A losing caller gets the current request back, so calls are idempotent. Terminal states never change. `answer` stores the response after winning the compare-and-set, then completes the waiters.
- **Waiting**: one `Sinks.One` per request id; callers subscribe to it. When the last waiting caller cancels, the request is cancelled (`node-cancelled`). The orchestrator cleanup calls `cancelExecution(executionId, "run-ended")` through an `ObjectProvider<InputBroker>` (setter, so the constructor and its tests do not change).
- **Deadlines**: absolute `deadline` on the request; `InputDeadlineSweeper` (`SmartLifecycle`) calls `sweep()` every `yukta.input.sweep-interval` only while `LeaderElection.isLeader()`. `FAIL` and `ESCALATE` (until phase 6) expire the request; `USE_DEFAULT` answers it as `Responder.SYSTEM`.
- **Limits** (`yukta.input.*`, `YuktaProperties.Input`, validated at start-up): open per execution and per session, `max-ttl` (a longer ttl is **refused**, rule `ttl`), `memory-max` finished requests in `InMemoryInputRequestStore`. A refusal is an `InputLimitException` and `yukta.input.denied{rule}`. The checks run before `createIfAbsent`, so a parallel burst can pass them by a few.
- **Redaction**: `InputRedactor` (prompt, context, escalation reason and advice) on top of `SecretRedactor`, the one list of secret patterns and key names (`LogSanitizer` in `mcp` uses it too). It also replaces `${env.X}` references and `yukta.input.redact-keys`. Events, the store and the log only ever see redacted text; the log never carries the prompt or an answer text.
- **Events and log**: `InputRequested`, `InputEscalated`, `InputAnswered`, `InputExpired`, `InputCancelled` on `ExecutionEventFeed`; one `ExecutionLogEvent.Type.INPUT` per change, payload `event` = `INPUT_REQUESTED` ... `INPUT_CANCELLED`. Code that reads the log by type ignores `INPUT` (tested in `ExecutionRecovery`, `LogRetention`, `RunAnalytics`, `StartIdempotency`).
- **Metrics**: `yukta.input.requests{kind,risk,outcome}` (asked, answered, defaulted, escalated, expired, cancelled), `yukta.input.wait{tier}`, `yukta.input.open`, `yukta.input.denied{rule}`.
- **Store contract**: `InputRequestStoreContract` in `plus/src/testFixtures/.../testkit`; the in-memory store runs against it from `plus` `ContractsTest`. Core keeps the broker tests (`InputBrokerTest`, virtual time and a mutable clock, no sleeping).
- **Answering** (`AnswerInputCommandProcessor`, `EscalateInputCommandProcessor`; both behind `InputCommandGuard`): leader check (`NotLeaderException`), request lookup (404), run match (409), `AnswerAuthorizer`, then `AnswerShape` (CHOICE and APPROVAL-with-options need an option id; STRUCTURED data must fit the `responseSchema` by `SchemaSubset` (type, properties, required, enum, items, `additionalProperties:false`; messages never repeat a value); TEXT needs text; QUERY takes anything), then `InputBroker.answer`. A refused answer leaves the request open. Answer after the request ended, or with a moved `expectedVersion`: 409. A repeat answer: accepted.
- **Who** (`ActorResolver`): reads `ControlActor.KIND_KEY` (written by `ApiKeyFilter` and `McpEndpointFilter` as `KEY`, by `SupervisorHost` as `SUPERVISOR`; `TOKEN` in phase 6), plus the resolved key (`CallerIdentity.CONTEXT_KEY`) for role and sessions. Never parse the actor string. No kind and no actor: a person when the key filters are open (or the single `yukta.api-key` matched), otherwise `UNAUTHENTICATED`; an actor with no kind is `UNAUTHENTICATED`. A supervisor that is not attached (a bean) has `canAnswer=false` and global scope.
- **Rules** (`DefaultAnswerAuthorizer`, replaceable `AnswerAuthorizer` bean in `DefaultsAutoConfiguration`): `audience`, `tier`, `risk`, `scope`, `separation`, in that order; each denial is an `InputForbiddenException` naming its rule (HTTP 403) and counts in `yukta.input.denied{rule}`. `HIGH` is human-only with no setting. Escalation skips `risk`. The default tier targets are `supervisor:*` and `role:OPERATOR` until routes exist.
- **Reading** (`InputRequestQueries`, used by REST, MCP and so the CLI): lists by session, workflow, run and states (newest first; terminal states read `InputRequestStore.list`, kept up to `memory-max`), `require` (404 for another run's request), `answer`, and `requireWaiting` before an answer or escalation: an answered request is `InputAnsweredException` (409 naming the stored decision and responder), expired or cancelled a `ConflictException`. A race that the pre-check misses still ends as the processor decides (a repeat answer accepted).
- **Askers** (phase 4): `WAIT_FOR_SIGNAL`, `requireApproval` (`ToolApproval`), `ASK_INPUT` and the `ask_for_input` tool of `MCP_TOOL_CALL` (`allowAskInput`; `LLM_CALL` with `allowAskInput` offers the tool, its action is wired to that node) all go through `InputAsk` in `plugin-api` and an `ObjectProvider<InputGateway>`; without a gateway bean they fail with a clear message. The model cannot lower risk below `inputRiskFloor` and cannot set audience, ttl or route.
- **Routes** (#1796, `service/input/route`): `InputRoute(name, tiers, onFinalTimeout)` and `Tier(name, responders, timeout, mode, quorum, minConfidence, type, settings)`, read from `yukta.input.routes.<name>` (`RouteSettings`) and checked at start-up. `RouteResolver` picks the route: spec `routeName` (unknown name is refused), the session tag `input.route`, `routes.default`, the built-in one-tier route (`supervisor:*`, `role:OPERATOR`). The broker puts the request in tier 0 (`tier`, `targets`, `tierDeadline`); `moveUp` goes to the next tier (state `ESCALATED`, version+1, votes cleared, new deadline; `supervisor:above` becomes concrete `supervisor:<id>` selectors through `TierTargets` and `EligibleSupervisors`), `skipUnreachable` hands on at once when a supervisor-only tier has no matching supervisor (`no-target`) or a quorum cannot be reached. `sweep` also fires on `tierDeadline`: next tier, or `finalTimeout` (route `onFinalTimeout`, then the spec's `onTimeout`) at the last one. `escalate` with no higher tier only flags the request. A supervisor answer below `minConfidence` becomes advice and moves up; in `QUORUM`/`UNANIMOUS` tiers it is a `Vote` (once per supervisor; a person always decides). Depth guard for supervisor runs: extension point in `create`, phase 8.
- **Log**: `INPUT_ANSWERED` and `INPUT_ESCALATED` carry request id, responder type and id, risk, and the rationale or reason cut to 500 characters.
