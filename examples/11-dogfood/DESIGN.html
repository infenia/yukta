Developing Yukta with Yukta

The dogfood loop: every build and check of this repo runs as a Yukta workflow on a local dev server, and a failed check is repaired by Claude models, cheapest first, before a developer has to step in.

A run

yk checkreads the changes, runs plan.sh, applies session.json, starts check
→
checkone tool call per planned stage, in order, cheap first
→
stage failsits output goes to heal
→
healfree fix, triage, model ladder
→
verifyonly if something was healed: the Gradle tasks of all stages once more

Everything ends in one line: RESULT status=<S> failed_node=<stage|-> healed=<stage:model/effort,..|-> execution=<id> session=<id>. Exit code 0 only on success. yk starts the dev server on demand; it is built from origin/main, so a run does not change under itself.

The scope comes from plan.sh: the changed Gradle modules get every stage, their dependents compile and test only, cli/ and ui/ get their own tools, and the repo checks (reuse, actionlint, docs links) run when their files changed. Stages are ordered cheapest first: reuse, actionlint, docs, spotless, cli formatting, compile, vet, tsc, eslint, style, spotbugs, tests, coverage, vulnerability and licence checks, security, build. licenses and security are never healed.

Workflows

Five fixed workflows, applied to a session per checkout and per command (check-<branch>-<hash of the path>, with -plan for yk check and -gradle for yk gradle and yk tool, so a fixer's own yk gradle cannot replace the workflows of the check it heals). What changes per run travels in the start payload, never in the graph. Each layer is one level of SUB_WORKFLOW nesting: check (0) → heal (1) → attempt (2) → claude or tool (3), inside the engine's depth limit of 5.

WorkflowJobCalls
toolRun one shell command in one project, once. A non-zero exit or a timeout ends at OUTCOME_TERMINAL FAILED; the caller decides what that means. Concurrency group tool.-
claudeOne headless Claude Code session (scripts/claude.sh); returns Claude's JSON result and cost. Concurrency group claude.-
attemptOne repair attempt at one model and effort: prepare, claude, claimed, format, judge (the guard), recheck, report.claude, tool
healRepair one failed stage: free fix, brief, triage, a ladder of attempts.tool, attempt
checkThe scoped gate: a tool call per stage, heal on a failure, then verify.tool, heal

Failures are data: process nodes use failureMode: CONTINUE with routeByExitCode, sub-workflow calls use routeByOutcome and engine.onError: ROUTE, so a caller always gets a port to route on instead of a crash. The script steps of heal and attempt are the actions of scripts/yukta-heal.sh (brief, triage-log, record-auto, healed, prepare, claimed, judge, report); each appends one JSON line to the events log.

Heal

1 · free fixspotlessApply, make fmt, prettier, eslint --fix, make mod-tidy. No model, no cost. Recheck decides.
→
2 · briefthe problem lines, at most 1000 characters for triage
→
3 · triagea CLASSIFY node asks the local System One model: easy, average or hard
→
4 · ladderrungs of model/effort, one attempt each

Triage

The label only picks the first rung. Below minProbability (0.3), or when the model is unreachable, heal starts at the default level (average). --triage off skips the call. The triage model and URL are in heal.json and overridden by YUKTA_TRIAGE_MODEL and YUKTA_TRIAGE_URL.

Ladders

LevelLadderFor
easyhaiku/low → sonnet/lowmechanical or small obvious fixes: formatting, an import, a header, one analyzer finding
averagehaiku/high → sonnet/lowone failing test, a few classes together, tests to add for coverage
hardsonnet/lowmany failures with one cause, concurrency, flaky or order-dependent, memory, build-wide changes

Each effort has a budget and a time box in heal.json: low $0.50 and 10 min, high $2 and 30 min. Every attempt is a fresh session (no resume): measured, a conversation cache is lost anyway when the model changes, and a fresh session carries only the brief and the previous attempt's summary. Opus is not on any ladder.

When a rung fails

  • The next rung gets the new failure output and the previous attempt's summary plus the files it changed.
  • An attempt that changed no file ends the ladder. A stronger model asked the same question rarely answers it differently; this saves the 15 to 20 times higher cost of the next rung. A timeout or crash still escalates.
  • The end of the ladder gives up: heal ends FAILED and check ends with failed_node = the stage.
  • --models can stop a rung before it starts: a model left out has its attempts end at once.

Verify

When anything was healed, the Gradle tasks of every planned stage run once more, because a fix can break a stage that ran before it. A failed verify goes back to heal as the stage verify (its command is the verify command, the formatter is spotless) instead of ending the run.

The guard

What Claude says is recorded but decides nothing. judge looks at what changed on disk, and only the recheck of the stage's own command makes an attempt a fix.

RejectedHow it is detected
Touching config/, build-logic/, gradle/, .github/, .claude/, this folder, REUSE.toml, *.gradle.ktschanged paths against a pattern
An added suppression: @SuppressWarnings("PMD"|"checkstyle"), @SuppressFBWarnings, NOPMD, CHECKSTYLE:OFF, @Disabled, spotless:offadded lines of the diff, and whole new files
Removed assertionsmore removed than added lines with assert, @Test or verify(
Test expectations changed with no code changedonly test files changed, and assertion lines were both removed and added (a test made to fit the code). A fix that edits a test and its code together passes.
A claimed fix with no changeclaimed fixed, nothing differs from the snapshot taken before the attempt

Fixers also never run git commit or git push (disallowed tools), and fixer-rules.md is the one constant system prompt, so every attempt shares the cached prefix.

The fixer session

One launcher for every headless Claude (scripts/_claude.sh, called by scripts/claude.sh), deliberately slim.

SettingWhy
--setting-sources project --strict-mcp-config --disable-slash-commands, CLAUDE_CODE_DISABLE_CLAUDE_MDS=1none of the user's plugins, skills, MCP servers or CLAUDE.md files (a measured 15.9k to 9.7k tokens of prefix); the project's hooks still load, they keep the Gradle guard
--tools Read,Edit,Write,Grep,Glob,Bash and an allowlist of Bash(./gradlew:*), make, go test, go vet, node_modules/.bin, codegraph, reuse, actionlint, mint, cda fixed tool list; the allowlist is resolved before auto mode's classifier, so the usual commands cost no classifier call
--permission-mode auto --permission-prompts nonea classifier reviews anything outside the allowlist; nothing can prompt in an unattended run, and Claude is told not to retry a denial. Needs Haiku 5.5 or Sonnet 4.6 and later, Claude Code 2.1.302 or later. The classifier defaults to Sonnet and adds a call per reviewed action.
ANTHROPIC_DEFAULT_HAIKU_MODEL=claude-haiku-5-5, ANTHROPIC_DEFAULT_SONNET_MODEL=claude-sonnet-5-5aliases move when a model ships; cost and behaviour of a rung must not
--max-budget-usd, --output-format json --json-schema {fixed, summary}, --no-session-persistencea cost cap per attempt, a parseable answer and cost, and no transcript left behind
--advisor $YK_ADVISOR (off unless set)experimental: a stronger model consulted at decision points, a possible replacement for the sonnet rung. Anthropic API only. Not yet settable per rung from heal.json.

A failed run is visible in the summary: claimed adds the result's subtype when Claude returned no answer, for example no answer from claude (error_max_budget_usd: …). The tool was checked against the headless documentation: the Bash(cmd:*) rule syntax is honoured, and --bare is not used because it needs an API key and skips the hooks.

Evidence

scripts/test-heal.sh covers the pipeline without API cost: two stages healed in turn (and no two fixers at once), a no-change attempt ending the ladder, an escalation, a failed verify going back to heal, and a hard triage starting at sonnet/low.

From planted-failure runs (format, style, compile, test, coverage, docs, a cli lint file). Small samples: they show the pipeline works and where it is weak, not rates.

  • A planted compile error was fixed by haiku/high on the first attempt for $0.0024 in 22 s; the whole check, with a second stage healed, took 193 s. Wall time is dominated by Gradle and tool runs; a Claude call is about 15 s.
  • Haiku attempts cost $0.002 to $0.006; a sonnet escalation costs $0.018 to $0.035. Escalation paid off in the deliberate escalation test and was wasted on the stages no code edit could fix.
  • The guard bug that mattered: grep -q on a pipe ends early and, under set -o pipefail, the writer's SIGPIPE read as "no match", so added suppressions got through. The text is now captured in a variable first.
  • A fixer treats an unexpected planted file as the developer's work and changes nothing; a fixer deleted an untracked run log that broke reuse lint.
  • One verify run reported a PMD violation after both stages had been healed, a second run was clean: flaky, and the reason for sending verify back to heal.

Engine gaps found while building

Things the workflow engine cannot do yet, and the workaround each one has here. G4 (nesting depth 5) does not bite the current five workflows; it will when issue and epic runs return.

#GapWorkaround
G1A command argument cannot be a list
PROCESS_EXECUTOR turns each command element into one string, so a task list in a start-payload key is one argument.		tool runs sh -c with the command in an environment variable; yk shell-quotes every argument.
G2No declared inputs or defaults
A workflow is only id, description, nodes and edges. A missing start key resolves to nothing, and a PROCESS_EXECUTOR timeout then falls back to 300 s.		Every caller passes every key (KEYS in gen-heal.py, PASS in gen-check.py).
G3Only workflows of the same session can be called
SUB_WORKFLOW looks the child up in the parent's session.		yk applies the whole library to every session it starts a run in.
G5Outcome FAILED does not fail the caller by itself
Without routeByOutcome a child that ended at OUTCOME_TERMINAL FAILED still has status SUCCESS.		Every call sets routeByOutcome: true and wires failure.
G6${…} cannot index a list
The variable resolver walks maps only, so results[0].stdout cannot be written as a path.		MAPPER nodes (PROJECTION, SpEL) flatten results[0]; script steps read whole results as JSON on stdin.
G7A timeout drops the output
On a process timeout the gateway returns exit -1 with an empty stdout.		The brief says the stage timed out; the fixer reads the run log.
G8Some SUB_WORKFLOW errors are never routed
The node's own timeoutSeconds, an unknown workflow and too deep a nesting fail the node even with routeByOutcome.		engine.onError: ROUTE and an error edge next to failure.
G9A sub-workflow cannot inherit the start payload
SUB_WORKFLOW's payload must be a map of resolved top-level values.		Every key is listed one by one; a key added to a contract is added to every caller.
G10BRANCH and MAPPER cannot read the start payload
SpEL sees only the message, so a start switch (heal, triage, auto) must first be copied into it.		The trigger copies it (CONSTANT_SOURCE), or a script step echoes it into its JSON output.
G11A ${payload} in a sub-workflow payload arrives as text
The value becomes the Java text of the map, not the map.		A MAPPER per stage (<stage>.fail) projects the failed output to a string, stdout.
G12The CLASSIFY answer is not in the node's task metadata
workflow status shows metadata: {} for the triage node.		A triage-log.<port> node on every triage port records the route as an event.
G13A script step with outputFormat: JSON must print nothing else
The engine merges stderr into stdout; one extra line and the output is not parsed.		Those steps print only JSON; claimed prints the live HEAL line; report always exits 0.

Open items

  • Timeouts lose the cost. A process timeout sends SIGTERM (exit 143) and records no result, so that attempt's spend is $0 in the records and the issue budget. stream-json would capture it.
  • Silent code-index failures. An issue run's --mcp-config entry that fails validation is skipped with a clean exit; the failure shows only in system/init, which plain json output lacks.
  • Docs stage. mint broken-links works locally (exit 1 on a bad link). A heal run once failed to clear it; the leading suspect was the spinner output hiding the report, which is now stripped. Unconfirmed.
  • Advisor. Compare haiku with --advisor sonnet against the haiku → sonnet ladder on the same failures before using it; it needs a per-rung field in heal.json.
  • Guard. A test expectation changed together with unrelated code still passes.
  • Rebuild. Issue and epic runs, yk heal report|analyze, steering commands, the Stop hook and the slash commands are in backup/; backup/README.md says how to bring each back.
