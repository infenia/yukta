# Ticket pipeline (work in progress)

TypeScript on Bun: `bun install` in this folder (through `yk tool -C examples/12-ticket bun install`), tests with `yk tool -C examples/12-ticket bun test`.

Turns a GitHub issue into a reviewed, tested draft PR: an architect writes a spec and a test-case table, a test writer and an implementer work one small step at a time inside hard guardrails, a reviewer signs off. Design: `design/plans/ticket-pipeline.md` (Epic #1872); answers to the open questions: `verify.md`.

| Path | What |
|---|---|
| `schemas/` | JSON Schemas of every artifact the roles exchange (spec, step packet, step result, failure digest, revision, review, test-writer result) |
| `fixtures/<schema>/` | one `valid.json` and several `invalid-*.json` per schema |
| `project.json` | the project profile: commands, conventions, high-risk paths, limits, budgets |
| `src/ticketkit.ts` | the deterministic tools (`bun src/ticketkit.ts SUBCOMMAND`; schemas are validated with `ajv`): `validate-schema NAME FILE`; `init ISSUE` (run dir, branch, worktree; `SKIPPED` and exit 3 without acceptance criteria or when the branch exists); `route RUN_DIR` (models, effort, `tests_mode` into `routing.json`); `validate-spec RUN_DIR` (design 8.1 and the sizing lint 11.3; writes `spec/validation.json` and `spec/spec.hash`); `gate-tests RUN_DIR` (after the test writer: applies the stubs, checks only stubs and locked tests changed, `[T#]` tags, compile, a red check per case from the JUnit / Vitest / `go test -json` report, trivial-test lint; then locks the tests in `spec/locked.json` and writes `spec/test_map.json`); per-step tools in `scripts/stepkit.py`: `pack-step` (one step's packet, byte-stable cache prefix, deny list), `scope-check` (the diff since the step base: write_files, locked hashes, suppressions, removed assertions, dependency files, forbidden imports, size), `regen` (generated files by command, never by hand), `free-fix` (formatters, never an attempt), `digest` (failure digest of at most 2 KB from `yk` output and JUnit XML), `event` (one `events.jsonl` line with token and cache fields from a claude result) |
| `../11-dogfood/fixer-rules/ticket-*.md` | the constant role files (`architect`, `test-writer`, `implementer`, `reviewer`), picked by `YK_ROLE` in claude.ts |
| `src/call.ts`, `src/flow.ts` | the glue of the workflows: `ticketkit call ROLE RUN` (one Claude call through `claude.ts --role`: prompt from files, answer validated with one retry, event line with tokens and cache fields) and `ticketkit flow preflight\|step-begin\|validate-step\|commit-step\|full-checks\|close` |
| `src/ladder.ts` | failure routing and escalation (`ticketkit ladder decide|heal|next-step|route-failure|build-revision|apply-revision|review-verdict|need-approval|pause-packet|ack-pause|final-fail`): the retry ladder (attempt 2 same model, attempt 3 one tier up, then the architect revises; short-circuits for BLOCKED, infra errors, licenses and security), heal for mechanical stages (everything outside `write_files` and any locked test is reverted and recorded), `baseline_failure`, revisions (completed steps immutable, spec v+1, changed cases only through the test writer), budgets (cost, wall clock, attempts, revisions: over a limit the run pauses with `human-packet.md` and waits for `yk approve|reject`) and the verdict override (a blocker or an unfaithful test turns APPROVE into CHANGES_REQUESTED) |
| `src/gen-ticket.ts`, `session.json` | generates the workflows `ticket`, `attempt_round`, `steps_round`, `step`, `finalize` and `escalate`; `--check` fails when the committed `session.json` is stale. `session.json` is generated: do not read or edit it |
| `src/github.ts` | the GitHub side (design 15.9): `ticketkit github intake` (open, assigned, Ready, criteria; a criterion that asks for secrets, a push to main, other repos, settings or skipped checks BLOCKS, such text elsewhere in the issue is ignored), `claim`, `plan-comment`, `dead-end` (issue back to Ready + a comment, worktree stays), `finish` (format, commit, push `issue/<n>`, draft PR with `Fixes #n`, the final `RESULT` line, spec summary, cost by role; fails without them). Never merges, never pushes main |
| `yk`, `src/yk-ticket.ts` | `yk ticket run <issue> [--detach [--notify]]`, `yk ticket status\|resume\|stop <issue\|execution>` (also `examples/12-ticket/yk run 123`); approvals use `yk approve\|reject` |
| `../11-dogfood/test/pickup.test.ts` | offline test of pickup mode A: `YUKTA_PICKUP_MODE=ticket` (or `$DEV_HOME/pickup-mode`) makes `pickup tick` run `yk ticket run <n> --detach` instead of handing the issue to a session |
| `src/waves.ts` | parallel step waves (design 11.2): `ticketkit waves next-wave|prepare|warm-wait|merge|check`. Two ready steps with disjoint `write_files` run at once (`max_parallel` 2, the `tool` group has two places), the second in its own worktree and branch from the same base, after the first has warmed the cache; they are merged in step order (a conflict is aborted and escalated to the later step) and a post-wave check runs on the merge. `ui/package.json`, the lockfiles and `shared_files` run alone |
| `src/report.ts` | `ticketkit report` / `yk ticket report`: first-try pass rate and mean attempts by (model, effort, complexity), cost share and cache hit ratio by role, `prefix_hash` mismatches, the BLOCKED rate (above 15% the steps are too small) |
| `ticketkit flow mutation` | pitest on the changed classes at medium or high risk (never `:boot`, `:plus:*`, `:test-support`); survivors above `mutation.max_survivor_rate` (0.25) reach the reviewer as a finding |
| `measurements.md` | the recorded wall-clock measurement of parallel against sequential steps |
| `test/waves.test.ts` | offline tests of waves, the mutation gate and the report (design 13.1 items 13, 20, 21; 15.13 item 31) |
| `src/decision.ts` | the local decision model (design 3.2, 15.8) through the `decide` helper of 11-dogfood: `ticketkit decision triage` (`triage_complexity`, `triage_risk`, after `route`), `cause` (tests and compile failures from attempt 2: spec_gap and spec_conflict revise, flaky reruns once) and `merge_risk` (0 to 10). All four start in `shadow` in `decisions.json` (bar 50 / 0.9): the static rule decides, the model's answer and the static label are logged for `yk stats --decisions`; `on` is a change of `"mode"` only. Unreachable or invalid: the static rule and one `WARN decision model unavailable` line. The triage URL of heal is a per-machine override: `YUKTA_TRIAGE_URL`, else `$DEV_HOME/triage.json`, else `heal.json` |
| `test/decision.test.ts` | offline test of the above against the fake Ollama (design 13.1 item 9, 15.13 item 34) |
| `test/ladder.test.ts`, `test/helpers.ts` | offline fault tests of the ladder, heal, revision, budgets and approvals (design 13.1 items 8, 10, 11, 12, 23; 15.13 items 27, 33) and the decision rules |
| `test/ticket.test.ts`, `src/walk-workflow.ts` | offline test of the pipeline: walks the generated workflows against a throwaway repo, a fake `gh` and a fake claude (happy path, `BLOCKED`, invalid JSON retried once, failing gate, scope violation, high risk) |
| `test/schemas.test.ts` | offline test (fake claude, no API cost) of the schemas, fixtures and roles |
| `test/spec.test.ts` | offline test of `init`, `route` and `validate-spec` on a throwaway git repo (design 13.1 items 5, 18, 19, 22; 15.13 items 24, 29) |
| `test/gate.test.ts` | offline test of `gate-tests` with a fake runner (design 13.1 items 6, 14, 15, 16, 17) |
| `test/step.test.ts` | offline test of the per-step tools (design 13.1 items 1-4, 7; 15.13 items 25, 26) |
