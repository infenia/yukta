# Ticket pipeline (work in progress)

Turns a GitHub issue into a reviewed, tested draft PR: an architect writes a spec and a test-case table, a test writer and an implementer work one small step at a time inside hard guardrails, a reviewer signs off. Design: `design/plans/ticket-pipeline.md` (Epic #1872); answers to the open questions: `verify.md`.

| Path | What |
|---|---|
| `schemas/` | JSON Schemas of every artifact the roles exchange (spec, step packet, step result, failure digest, revision, review, test-writer result) |
| `fixtures/<schema>/` | one `valid.json` and several `invalid-*.json` per schema |
| `project.json` | the project profile: commands, conventions, high-risk paths, limits, budgets |
| `ticketkit` | the deterministic tools (python3 `jsonschema` >= 4.18 needed): `validate-schema NAME FILE`; `init ISSUE` (run dir, branch, worktree; `SKIPPED` and exit 3 without acceptance criteria or when the branch exists); `route RUN_DIR` (models, effort, `tests_mode` into `routing.json`); `validate-spec RUN_DIR` (design 8.1 and the sizing lint 11.3; writes `spec/validation.json` and `spec/spec.hash`); `gate-tests RUN_DIR` (after the test writer: applies the stubs, checks only stubs and locked tests changed, `[T#]` tags, compile, a red check per case from the JUnit / Vitest / `go test -json` report, trivial-test lint; then locks the tests in `spec/locked.json` and writes `spec/test_map.json`); per-step tools in `scripts/stepkit.py`: `pack-step` (one step's packet, byte-stable cache prefix, deny list), `scope-check` (the diff since the step base: write_files, locked hashes, suppressions, removed assertions, dependency files, forbidden imports, size), `regen` (generated files by command, never by hand), `free-fix` (formatters, never an attempt), `digest` (failure digest of at most 2 KB from `yk` output and JUnit XML), `event` (one `events.jsonl` line with token and cache fields from a claude result) |
| `../11-dogfood/fixer-rules/ticket-*.md` | the constant role files (`architect`, `test-writer`, `implementer`, `reviewer`), picked by `YK_ROLE` in `claude.sh` |
| `scripts/call.py`, `scripts/flow.py` | the glue of the workflows: `ticketkit call ROLE RUN` (one Claude call through `claude.sh --role`: prompt from files, answer validated with one retry, event line with tokens and cache fields) and `ticketkit flow preflight\|step-begin\|validate-step\|commit-step\|full-checks\|close` |
| `scripts/gen-ticket.py`, `session.json` | generates the workflows `ticket` and `step` (walking skeleton: one step, no retry ladder, approvals or PR yet); `--check` fails when the committed `session.json` is stale. `session.json` is generated: do not read or edit it |
| `scripts/github.py` | the GitHub side (design 15.9): `ticketkit github intake` (open, assigned, Ready, criteria; a criterion that asks for secrets, a push to main, other repos, settings or skipped checks BLOCKS, such text elsewhere in the issue is ignored), `claim`, `plan-comment`, `dead-end` (issue back to Ready + a comment, worktree stays), `finish` (format, commit, push `issue/<n>`, draft PR with `Fixes #n`, the final `RESULT` line, spec summary, cost by role; fails without them). Never merges, never pushes main |
| `yk`, `yk-ticket.sh` | `yk ticket run <issue> [--detach [--notify]]`, `yk ticket status\|resume\|stop <issue\|execution>` (also `examples/12-ticket/yk run 123`); approvals use `yk approve\|reject` |
| `../11-dogfood/scripts/test-pickup-ticket.sh` | offline test of pickup mode A: `YUKTA_PICKUP_MODE=ticket` (or `$DEV_HOME/pickup-mode`) makes `pickup tick` run `yk ticket run <n> --detach` instead of handing the issue to a session |
| `scripts/test-ticket.sh`, `scripts/walk-workflow.py` | offline test of the skeleton: walks the generated workflows against a throwaway repo, a fake `gh` and a fake claude (happy path, `BLOCKED`, invalid JSON retried once, failing gate, scope violation, high risk) |
| `scripts/test-schemas.sh` | offline test (fake claude, no API cost) of the schemas, fixtures and roles |
| `scripts/test-spec.sh` | offline test of `init`, `route` and `validate-spec` on a throwaway git repo (design 13.1 items 5, 18, 19, 22; 15.13 items 24, 29) |
| `scripts/test-gate.sh` | offline test of `gate-tests` with a fake runner (design 13.1 items 6, 14, 15, 16, 17) |
| `scripts/test-step.sh` | offline test of the per-step tools (design 13.1 items 1-4, 7; 15.13 items 25, 26) |
