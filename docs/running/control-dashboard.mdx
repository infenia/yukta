<Info>
  **In plain terms:** `/control` in the web UI is one page that shows how the server is doing right now and lets you steer it: change the run limit, drain it, and attach supervisors.
</Info>

## Panels

| Panel | What it shows |
|---|---|
| Command strip | Runs per minute and p95 duration with their 1 h trend and change, success rate over 24 h, approvals waiting (opens the overview, where they are answered), running and waiting runs, worker slots in use, and model spend over the last hour |
| Capacity | Running against the limit, the concurrent run limit (0 is unlimited) as a knob, the drain switch and refused starts per reason. A refused change is put back. |
| Throughput, latency | Finished runs by status and the p50/p95/p99 duration and queue wait for the chosen range (`15m` to `24h`). Control commands are marked under the chart: a click opens the run they steered, or the control audit for one that names no run, such as a limit change |
| Live runs | Runs in progress: nodes done, time so far against the workflow's usual p95 (outlined when slower), and pause, resume and stop. Stepping is per node, in the run view the name links to |
| Runs, last 24 hours | One cell per minute, darker with more runs and red with failures |
| Plugins | Each plugin type's runs, failure share and mean duration |
| Control bus, workers, system | Heartbeat age per node (green, amber, red), slots in use per worker, heap, CPU and threads, the longest GC pause and dropped events |
| AI usage | Tokens in and out and spend per provider, MCP tool calls, failed calls and refused heavy calls. These meters are server-wide, so a scoped view says so |

The **Scope** filter lists the whole server, every session and the workflows the page knows of (the chosen session's, each session's last run and the runs going now); every panel except capacity, system and AI usage follows it. The scope, range and live/paused state are kept in the URL (`?scope=workflow:<id>&range=6h&live=0`), so a view can be shared. Metrics are sampled in memory since startup and come from `GET /api/metrics/series` and `GET /api/metrics/snapshot`; see [Observability](/running/observability).

The **Activity** tab is the live event feed and the **Audit** tab lists every control command with who sent it (`/control?tab=audit`).

## Kiosk mode

**Kiosk** opens a full-screen wall display: the command strip stays, and the panels cycle in three groups every 15 seconds with larger type. Hovering pauses the cycle; the dots jump to a group. **Esc** (or **Exit**) leaves it.

## Supervisors

The page lists every supervisor as a card with its scope, its decisions, and switches for dry run and enabled. A supervisor can apply to every run, one session or one workflow, and the session and workflow pages show the ones that apply there. See [Supervisors](/running/supervisors). Attaching needs an `ADMIN` key.

## Prometheus

The Prometheus registry is on the class path but the endpoint is off by default. To scrape it, set `management.endpoints.web.exposure.include=health,info,metrics,prometheus` and point the scraper at `/actuator/prometheus`. The dashboard does not need it.
