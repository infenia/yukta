# Configuration reference

Every setting that changes how the server admits, runs, stores and protects runs, plus the fixed limits no setting changes. "Off" means the feature is disabled until set. Defaults were checked against `YuktaProperties`, `SessionConfigProperties`, `TrackerProperties`, `MetricsProperties`, `PluginLogStoreConfig` and the `@Value` and `Environment` reads in `web`, `mcp`, `core` and `plugin-api`; the rows marked "not re-checked" were carried over from the previous documentation.

The alpha release may change names and defaults.

## How settings are supplied

| Source | Form | Example |
|---|---|---|
| Command-line argument | `--key=value` | `--yukta.execution.max-concurrent=20` |
| Environment variable | key upper-cased, `.` and `-` replaced by `_` | `YUKTA_EXECUTION_MAX_CONCURRENT=20` |
| Properties file | `key=value` | `yukta.execution.on-limit=REJECT` |
| System property | `-Dkey=value` before the program arguments | `-Dyukta.script.timeout-ms=5000` |

Durations take a unit (`30s`, `10m`, `1h`); `0` means off where the row says so. Settings marked **system property only** are read with `Integer.getInteger`-style calls and ignore the environment and the properties file: `yukta.script.*`, `yukta.spel.*`, `yukta.streams.*`, `yukta.rate-limit-per-minute`, `yukta.auth-failures-per-minute`. `yukta.variables.allowed` is read as a system property or as `YUKTA_VARIABLES_ALLOWED`. Secrets are read only from `YUKTA_SECRET_*` environment variables.

A native binary activates the `prod` profile itself unless `--spring.profiles.active=...` is passed as an argument. Setting `SPRING_PROFILES_ACTIVE=postgres` alone replaces `prod`; name both (`prod,postgres`).

Settings that store state on disk (`yukta.session.store-type=file`, `yukta.execution-log.dir`, `yukta.restart.dir`, `yukta.session-memory.dir`) need the Plus edition; the Community build refuses them at start-up. See [Licensing and editions](/reference/licensing).

## Server and network

| Property (environment variable) | Type | Default | Effect |
|---|---|---|---|
| `server.address` (`YUKTA_SERVER_ADDRESS`) | string | `127.0.0.1` | Bind address. A non-loopback value needs an API key or the server refuses to start. The container image sets `0.0.0.0`. |
| `server.port` (`SERVER_PORT`) | int | `9858` | HTTP port for the API, the web UI and `/mcp`. |
| `spring.codec.max-in-memory-size` (`YUKTA_LIMITS_MAX_BODY`) | size | `1MB` | Largest request body; larger gets `413`. |
| `spring.profiles.active` (`SPRING_PROFILES_ACTIVE`) | string | `prod` | Profile. `bootRun` uses `dev`. |
| `management.endpoints.web.exposure.include` | list | `health,info,metrics` | Exposed management endpoints under `/actuator`. |

## Admission and run limits

`yukta.execution.*` is `YuktaProperties.Execution`; `0` means no limit unless stated.

| Property | Type | Default | Effect |
|---|---|---|---|
| `yukta.execution.max-concurrent` | int | `0` | Runs at once, total. Excess starts wait or are refused. |
| `yukta.execution.max-concurrent-children` | int | `0` | Child runs (sub-workflows) alive at once, apart from the run slots. |
| `yukta.execution.max-concurrent-per-workflow` | int | `0` | Runs of one workflow at once. |
| `yukta.execution.max-concurrent-per-session` | int | `0` | Runs of one session at once. |
| `yukta.execution.queue-capacity` | int | `100` | Waiting starts; one more is refused with `429`. |
| `yukta.execution.queue-capacity-per-workflow` | int | `0` | Waiting starts of one workflow. |
| `yukta.execution.on-limit` | enum | `QUEUE` | `QUEUE` holds a start as `QUEUED`; `REJECT` refuses it with `429`. |
| `yukta.execution.queue-timeout` | duration | `0` | A start that waits longer ends `TIMED_OUT`. |
| `yukta.execution.max-starts-per-minute` | int | `0` | Starts per workflow and minute. |
| `yukta.execution.timeout` (`YUKTA_EXECUTION_TIMEOUT`) | duration | `1h` | Run deadline; paused time does not count. |
| `yukta.execution.shutdown-timeout` | duration | `30s` | Time running runs get at server stop. |
| `yukta.stop.drain-timeout` | duration | `30s` | How long a `DRAIN` stop waits. |
| `yukta.start.idempotency-ttl` | duration | `10m` | Window in which a repeated `Idempotency-Key` returns the first run id. |
| `yukta.start.idempotency-max-keys` | long | `100000` | Idempotency key cache size. |
| `yukta.mcp.start-dedupe-window` | duration | `30s` | MCP `start_workflow` without a key: a repeat for the same session and workflow within it returns the first run id. `0` turns it off. |
| `yukta.concurrency.groups.<name>` | int | unset (no limit) | Limit of nodes with `engine.concurrencyGroup=<name>` running at once. |
| `yukta.priority`, `yukta.version` (start payload keys) | number, string | `0`, latest | Run priority (higher first) and saved version to run. Both need the ADMIN role, or no key configured. |

## Input requests

| Property | Type | Default | Effect |
|---|---|---|---|
| `yukta.input.default-ttl` | duration | `1h` | Life of a request whose spec sets none; at most `max-ttl`. |
| `yukta.input.max-ttl` | duration | `24h` | Longest ttl a request may ask for. |
| `yukta.input.max-open-per-execution` | int | `5` | Open requests per run. |
| `yukta.input.max-open-per-session` | int | `50` | Open requests per session. |
| `yukta.input.memory-max` | int | `10000` | Finished requests kept in memory. |
| `yukta.input.sweep-interval` | duration | `1s` | How often overdue requests are ended. |
| `yukta.input.retention` | duration | `30d` | How long a finished request is kept before the hourly purge. |
| `yukta.input.redact-keys` | list | `[]` | Context keys whose value is replaced, besides built-in secret names. |
| `yukta.input.routes.<name>` | object | none | A named route: `tiers[]` (each `name`, `responders[]`, `timeout`, `mode` `FIRST`/`QUORUM`/`UNANIMOUS` default `FIRST`, `quorum` 2 or more with `QUORUM`, `minConfidence` 0 to 1, `type` `HUMAN`/`AUTO`, `settings`) and `onFinalTimeout` (`FAIL` or `USE_DEFAULT`). The route `default` applies when a request and its session name none. A bad route stops start-up. |
| `yukta.input.token-secret` | string | random per start | Signing secret of one-time answer tokens; unset tokens do not survive a restart. |

A tier name matches `[A-Za-z0-9._-]{1,64}`. A tier's `type` defaults to `AUTO` when every responder starts `supervisor:`, otherwise `HUMAN`.

## Fixed limits

| Limit | Value |
|---|---|
| Nodes per workflow | 500 |
| Edges per workflow | 2000 |
| Assignments per session or workflow | 20 |
| Saved versions per workflow | 20 |
| Sub-workflow nesting depth | 5 |
| Supervisor chain depth | 4 |
| Retry attempts | 1 to 10 |
| Edge buffer size | 1 to 100000 |
| Message history | 64 nodes |
| Pending log lines | 10000, then dropped |
| Echoed node output in logs | 2048 characters |
| Live log buffer per stream | 1024 lines |
| SSE keep-alive | every 15 s |
