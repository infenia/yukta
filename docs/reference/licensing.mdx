<Info>
  **In plain terms:** the Yukta you get by default is free under the Apache-2.0 licence. Saving state to disk is a separate, optional part under the AGPL. Larger setups (PostgreSQL, clustering, single sign-on) are a separate commercial edition.
</Info>

## The editions

| Edition | Licence | What it adds | Where it lives |
|---|---|---|---|
| **Community** | Apache-2.0 | The engine, REST and MCP interfaces, web UI, CLI, all built-in plugins, in-memory state | This repository, everything outside `plus/` |
| **Plus** | AGPL-3.0-only, or a commercial licence | State on disk (sessions, workflow definitions, the execution log, checkpoints, chat history), PostgreSQL storage with high availability, and remote workers | This repository, the `plus/` directory |
| **Enterprise** | Commercial | Enterprise security, multi-tenancy and other features built in a separate private repository that does not exist yet. PostgreSQL, high availability and remote workers are planned to move there later | A separate private repository |

The default build, the Docker image and the installers are the Community edition.

## Community: what to know

State lives in memory and is lost when the server restarts. Keep workflow definitions in files and apply them with the CLI (`yukta session apply`) after a restart, or build the Plus edition.

If a setting that needs disk storage is present, the Community build refuses to start and says so, instead of quietly running in memory:

| Setting | Needs |
|---|---|
| `yukta.session.store-type=file` | Plus |
| `yukta.execution-log.dir` | Plus |
| `yukta.restart.dir` | Plus |
| `yukta.session-memory.dir` | Plus |
| `yukta.session.store-type=postgres`, `yukta.ha.mode=postgres` | Plus, with `-Pyukta.persistence=postgres` |
| `yukta.workers.*`, `engine.placement` | Plus, with `-Pyukta.workers=true` |

## Plus: what to know

Build it with `-Pyukta.edition=plus`; add `-Pyukta.persistence=postgres` for PostgreSQL and `-Pyukta.workers=true` for remote workers. Because the build combines Apache and AGPL code, the Plus build as a whole is covered by the AGPL.

- Running it unmodified, inside your company or for your customers, needs nothing more.
- If you modify it and let other people use it over a network, the AGPL (section 13) requires you to offer them your modified source. A Plus server shows where its source is under `edition` in `/actuator/info`.
- If you cannot accept the AGPL, a commercial licence is available from Infenia Private Limited.

Named API keys, roles and session-limited keys are planned for Enterprise but are still in the public build today; they move when the Enterprise repository exists.

## Extending Yukta

An extension is a module that replaces one of the single-server defaults or adds a feature to a Plus build.

- **The hooks are Apache-2.0 and live in `core`**: the stores (`SessionConfigStore`, `WorkflowDefinitionStore`, `ExecutionLogStore`, `NodeCheckpointStore`, `KeyValueStore`, `SessionHistoryStore`), `LeaderElection`, `RemoteNodeExecutor`, `ApiAuthenticator` and `AuditSink`. A module provides a bean of the same type and the default steps aside. The community build must never depend on `plus`, so these cannot move there.
- **The integration layer is AGPL-3.0-only and lives in `plus`**: the `EnterpriseModule` extension API and its registry (version check, features, licence verification hook), the `EditionInfo` of a Plus or Enterprise build, and the contract tests (`testFixtures` of `plus`) that a store or election must pass. A module built on this layer is part of a Plus build and follows the AGPL; ask Infenia about a commercial licence if that does not suit you.
- Infenia's own Enterprise modules are built under Infenia's copyright and are not bound by the AGPL for that reason.
- How far the AGPL reaches into a module that only implements the Apache hooks is a legal question that this file does not settle, and it is not legal advice.
