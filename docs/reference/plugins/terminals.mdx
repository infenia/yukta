# Terminal reference

A terminal consumes messages and ends a branch; it has no output ports and nothing can be wired from it. All terminals are always part of the server. The default node timeout is 30 seconds idle.

## `CONSOLE_TERMINAL`

Logs each payload.

- **Options:** none.
- **Behaviour:** writes the payload at `DEBUG`; at `INFO` only a message count appears. Payloads can carry personal data or secrets, so leave `DEBUG` off for sensitive branches.

```json
{ "nodeId": "end", "type": "CONSOLE_TERMINAL", "config": {} }
```

## `NOTIFY_TERMINAL`

Notifies once per message, one at a time, in order. By default it sends a JSON webhook (`POST {"text": "..."}`, Slack-compatible); with `target: inbox` it raises a notification in the Yukta inbox instead.

| Option | Type | Default | Required | Description |
|---|---|---|---|---|
| `target` | `webhook` or `inbox` | `webhook` | no | `webhook` posts to `url`; `inbox` raises a notification for people to see in the bell, the Inbox page, the CLI and MCP. |
| `url` | string | none | for `webhook` | Webhook URL; `https`, or `http` for localhost only. Used as written; `${...}` is not resolved. Not needed for `inbox`. |
| `title` | string | none | for `inbox` | One line; at most 200 characters. |
| `severity` | `INFO`, `WARN` or `ERROR` | `INFO` | no | Severity of an inbox notification. |
| `audience` | list of `role:VIEWER`, `role:OPERATOR`, `role:ADMIN` or `key:<name>` | `role:OPERATOR` | no | Who sees an inbox notification, limited to the sessions their key reaches. A comma-separated string works too. |
| `text` | string | none | no | Fixed text; otherwise the payload's `text` field, or the payload as a string. |
| `timeoutMs` | number | `10000` | no | Request timeout in milliseconds. |
| `failureMode` | `ERROR` or `CONTINUE` | `ERROR` | no | `ERROR` fails the node on a non-2xx response (a redirect counts, and is never followed); `CONTINUE` logs it and keeps sending. |

- **Egress:** the URL is checked against `yukta.egress.*`.
- **Inbox:** the text (or the payload) becomes the body, the category is `workflow`, and the session, workflow, run and node are the node's own. A run may raise 20 notifications a minute and 200 in all; beyond that the node fails with an error that names the limit. Existing configurations without `target` are unchanged. A plugin of your own raises the same through `NotificationGateway`.
- **Errors:** `url is not a valid URL`; `url must be https (http only for localhost)`; `target must be webhook or inbox`; `title is required` (inbox); `severity must be INFO, WARN or ERROR`; `Not an audience selector`.

```json
{ "nodeId": "alert", "type": "NOTIFY_TERMINAL", "config": { "url": "https://hooks.slack.com/services/T000/B000/XXXX", "text": "Quality gate failed", "failureMode": "CONTINUE" } }
```

```json
{ "nodeId": "tell", "type": "NOTIFY_TERMINAL", "config": { "target": "inbox", "title": "Nightly report ready", "severity": "INFO", "audience": ["role:OPERATOR"] } }
```

## `OUTCOME_TERMINAL`

Names the exit a run took so a supervisor (or a parent `SUB_WORKFLOW`) can act on it. Put one at the end of each exit.

| Option | Type | Default | Required | Description |
|---|---|---|---|---|
| `outcome` | `SUCCESS`, `RETRY`, `ESCALATE` or `FAILED` | none | yes | `SUCCESS`: all done; `RETRY`: the cause was repaired, run again; `ESCALATE`: needs a fixer; `FAILED`: give up. |
| `restartFrom` | string | start of the workflow | no | For `RETRY` and `ESCALATE`: the node to restart from. |
| `reason` | string | none | no | Free text for the supervisor and the log. |

- **Behaviour:** the outcome, `restartFrom` and `reason` are added to the metadata of the node's `SUCCESS` status event, only when the run reached the node.
- **Errors:** `outcome must be one of [ESCALATE, FAILED, RETRY, SUCCESS]`.

```json
{ "nodeId": "give-up", "type": "OUTCOME_TERMINAL", "config": { "outcome": "ESCALATE", "restartFrom": "build", "reason": "needs a fixer" } }
```

## `REPLY`

After alpha.5. Answers the caller that started the run with `?wait=<seconds>` (`POST /api/workflow/start` or `POST /hooks/{sessionId}/{path}`): the call returns `200` with the payload of the first message that reaches this node in `data.reply`. A workflow can then serve as a synchronous HTTP API.

- **Options:** none.
- **Behaviour:** the trigger puts the caller's reply key on its message as `replyTo`, and every message derived from it carries it on. The first message to arrive answers; later ones, and messages of a run that nobody waits for, are skipped. Several `REPLY` nodes may share a run; the first answer wins.
- **Wait:** `?wait=` is capped by `yukta.reply.max-wait` (default `30s`). When it ends first the call returns `202` with only the execution id, as without a wait, and the run goes on. A repeated idempotent start returns the first run, which answers nobody: it gets `202`.
- **Limit:** the wait lives on the server that took the call, so the run must be on that server.

```json
{ "nodeId": "answer", "type": "REPLY", "config": {} }
```

```bash
curl -X POST 'http://127.0.0.1:9858/api/workflow/start?wait=20' -H 'Content-Type: application/json' \
  -d '{"sessionId": "s", "workflowId": "w", "payload": {"name": "ada"}}'
# 200 {"data": {"executionId": "…", "reply": {"greeting": "hi ada"}}, …}
```

## `SUPERVISOR_DECISION`

Ends a workflow that decides for a supervisor with its commands. The message it receives holds `{"commands": [{"type": "PauseWorkflow", "executionId": "..."}]}`; every command must be one the [supervisor contract](/reference/supervisors/contract) reads, or the run fails.

| Option | Type | Default | Required | Description |
|---|---|---|---|---|
| `outcome` | `SUCCESS`, `RETRY`, `ESCALATE` or `FAILED` | `SUCCESS` | no | `SUCCESS` sends the commands; `ESCALATE` hands the request up; `RETRY` runs once more; `FAILED` means no opinion. |
| `restartFrom` | string | start of the workflow | no | As for `OUTCOME_TERMINAL`. |
| `reason` | string | none | no | As for `OUTCOME_TERMINAL`. |

- **Limit:** a decision holds at most 10 commands (`A decision holds at most 10 commands, not <n>`).

```json
{ "nodeId": "decide", "type": "SUPERVISOR_DECISION", "config": {} }
```
