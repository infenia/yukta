Each example is a complete workflow for a job you probably recognise: an agent that must not skip verification, a deploy that needs approval, a nightly load that must reject bad rows. Find the one closest to yours, run it, then change it. The ten use-case examples are written to be copied: each README lists which nodes to change and which stand-in to swap for a model call.

They run offline with fixed rules and no model, so you can try them anywhere. Every example is a folder in the repository's [`examples`](https://github.com/infenia/yukta/tree/main/examples) directory with a `session.json` and a `run.sh` that applies the session, starts the run, answers any approval itself and prints `PASS` or `FAIL`.

## Run one

You need a running server, `curl`, `jq` and a copy of the repository.

```bash
git clone https://github.com/infenia/yukta.git && cd yukta
./examples/04-loan-approval/run.sh   # one example
./examples/run-all.sh                # all of them
```

<Note>
  Examples 01, 02, 03 and 08 run operating-system commands, which Yukta refuses by default. Allow only what they need, for example `YUKTA_PROCESS_ALLOWED_COMMANDS=sh,echo`; each README names its set. Example 08 also needs `python3`. Example 09 needs an LLM endpoint (OpenAI-compatible, Anthropic or Ollama). Set `YUKTA_API_KEY` if your server requires a key. See [Security](/operations/security).
</Note>

## Use-case templates

| # | Pain point | What it shows |
|---|---|---|
| [02](https://github.com/infenia/yukta/tree/main/examples/02-agent-verification) | An AI coding agent skips tests and says "done" | Verification gates and a bounded fix loop before "done" exists |
| [03](https://github.com/infenia/yukta/tree/main/examples/03-release-approval) | Production deploy that needs a person, then a check | Approval with a timeout, smoke check, rollback |
| [04](https://github.com/infenia/yukta/tree/main/examples/04-loan-approval) | Approve clear cases, send borderline ones to a person | Rule scoring, human review, stripping sensitive fields |

## How Yukta develops itself

[Example 11](https://github.com/infenia/yukta/tree/main/examples/11-dogfood) is the workflow the Yukta team runs on its own code. It runs the full `gradle check` as a staged workflow. When a stage fails, a repair chain applies a formatter fix, then asks headless Claude Code for a fix, and runs the stage again. It needs a Yukta checkout and Claude Code, so it is a reference rather than a starter.
