Each example is a complete workflow for a job you probably recognise: an agent that must not skip verification, a deploy that needs approval, a PR risk gate, a nightly event load that must reject bad rows. Find the one closest to yours, run it, then change it. The use-case examples are written to be copied: each README lists which nodes to change and which stand-in to swap for a model call.

Every example is a folder in the repository's [`examples`](https://github.com/infenia/yukta/tree/main/examples) directory with a `session.json` and a `run.sh` that applies the session, starts the run, answers any approval itself and prints `PASS` or `FAIL`. The examples are grouped by what they need to run.

## Categories

| Category | What you need | Examples |
|---|---|---|
| **1. Standalone** | Only the Yukta server. Allow the `sh` and `echo` commands. | Release approval, PR risk gate, dependency updates, model promotion, security findings, input pull, supervisor profiles, supervisor workflow, inbox notification, hello world |
| **2. Free dependencies** | Free tools on the machine (`git`, `python3`, `go`, `uv`, `bun` or `node`) or a stand-in for an outside service that the example starts itself. | Agent verification, alert triage, an MCP agent, supervisor agents, check out and run an app, a CI pipeline |
| **3. Paid tools** | An AI agent CLI (Claude Code, Codex) or a hosted model. The examples run against a fake agent unless you configure the real tool. | Agent session walkthrough, agent console |

## Run one

You need a running server, `curl`, `jq` and the `examples/` folder. You do not need to clone the repository: this downloads it as one archive and keeps only that folder (on macOS leave out `--wildcards`; on Windows use Git Bash).

```bash
curl -fsSL https://codeload.github.com/infenia/yukta/tar.gz/refs/heads/main | tar -xz --strip-components=1 --wildcards '*/examples'
./examples/1-standalone/03-pr-risk-gate/run.sh   # one example
./examples/run-all.sh 1                          # one category: 1, 2, 3 or all
```

## Run the server for every example

One server can run all of them. [Install the server](/get-started/install) or use the Docker image, then start it with every plugin on, the commands the examples run allowed, and the temp folder readable (examples 18 and 19 clone into it):

```bash
export YUKTA_PLUGINS_ENABLED=all
export YUKTA_PROCESS_ALLOWED_COMMANDS=sh,echo,shuf,python3,git,uv,bun,node,npm   # npm.cmd on Windows
export YUKTA_VARIABLES_ALLOWED=java.io.tmpdir
export YUKTA_AI_PRESETS_DIR=$PWD/examples/3-paid-tools/16-agent-console/agent-harnesses   # example 16
yukta                      # the installed server; from a source checkout: ./gradlew bootRun
```

Then run the examples from the folder where you extracted `examples/`. Set `YUKTA_API_KEY` if you gave the server a key (`YUKTA_API_KEYS_0_NAME`, `_KEY` and `_ROLE=ADMIN`).

```bash
./examples/run-all.sh                         # all of them, with a summary
./examples/2-free-deps/18-todo-run/run.sh     # or one
```

A server that allows less still runs the rest; an example it cannot run reports `SKIP` (exit 3) and names the missing setting. What each example needs:

| Example | Commands the server may run | Also on the machine |
|---|---|---|
| 01, 03, 04, 05, 06, 07, 09 | none | |
| 02 release approval | `sh` | |
| 10 inbox notification | `echo` | |
| 11 agent verification | `sh`, `echo` | `git` |
| 12 alert triage | `sh` | `python3` (its local pager stand-in) |
| 13 MCP agent | none | `curl`, `jq` |
| 14 supervisor agents | none | `python3`, `go` |
| 15 agent session | the agent CLI, for example `claude` | the agent CLI, logged in (walkthrough, no `run.sh`) |
| 16 agent console | `sh` | `YUKTA_AI_PRESETS_DIR` (see below) |
| 17 ask a random question | `echo`, `shuf` | `shuf` (GNU coreutils) |
| 18 check out and run, 19 CI pipeline | `git`, `uv`, `bun`, `node`, `npm` (`npm.cmd` on Windows) | `git`, `uv`, and `bun` or `node`; free ports 8000 and 5173 for 18 |

<Note>
  On Windows, run the scripts from Git Bash (it provides `bash`, `curl`, `sh` and `git`) and start the server there too, so it finds the same tools. `shuf`, `sh` and `go` have to be installed for the examples that use them.
</Note>

## How Yukta develops itself

The workflow the Yukta team runs on its own code lives in its own repository, [yukta-dogfood](https://github.com/infenia/yukta-dogfood). It runs the full `gradle check` as a staged workflow. When a stage fails, a repair chain applies a formatter fix, then asks headless Claude Code for a fix, and runs the stage again. It needs a Yukta checkout and Claude Code, so it is a reference rather than a starter.
