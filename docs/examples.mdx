Each example is a complete, small workflow for a common job. Find the one closest to yours, run it, then change it.

They follow the same path as Yukta itself: plain automation first, then AI added as a step, then AI driving the workflow.

| If you want to | Start with |
|---|---|
| Run a fixed sequence of steps with no AI, such as a CI gate | 01, 03, 04 |
| Move and reshape data | 02, 05 |
| Route on outcomes and alert on failures | 06, 07, 08 |
| Put a model inside a workflow | 09 |
| Let an AI agent create, run and watch workflows | 10 |

The picture above is example 03. Every example lives in the repository's [`examples`](https://github.com/infenia/yukta/tree/main/examples) folder with a script that applies the session, starts the run and prints `PASS` or `FAIL`.

## Run one

You need a running server, `curl` and `jq`.

```bash
./examples/03-ci-pipeline/run.sh   # one example
./examples/run-all.sh          # all of them
```

<Note>
  Examples 01, 03, 04, 06, 07 and 08 run operating-system commands, which Yukta refuses by default. For a local trial, start the server with `YUKTA_PROCESS_ALLOW_ANY=true`. See [Security](/operations/security). Example 09 needs an LLM endpoint (OpenAI-compatible, Anthropic or Ollama). Set `YUKTA_API_KEY` if your server requires a key.
</Note>

<Warning>
  Example 10 does not work on the native `0.1.0-alpha.2` server yet: its MCP tools fail ([#773](https://github.com/infenia/yukta/issues/773)). Run it from source until that is fixed.
</Warning>

## The ten examples

| # | Job | What it shows |
|---|---|---|
| 01 | Smallest end-to-end check | One trigger, one processor, one terminal |
| 02 | Pass data in and reshape it | Starting a run with a payload |
| 03 | CI gate that passes or fails | Routing on a command's exit code |
| 04 | Quality gate on metrics | Branching on values in the payload |
| 05 | Batch data pipeline | Split, filter, map |
| 06 | Monitor with an alert path | Routing on an HTTP status |
| 07 | One event to several channels | Fan-out to many recipients |
| 08 | Retry until ready | Bounded repetition |
| 09 | Chat agent with per-user memory | Model calls with memory |
| 10 | An AI agent drives Yukta | Using Yukta over MCP |
