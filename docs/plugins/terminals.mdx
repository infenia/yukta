<Info>
  **In plain terms:** a terminal is where a path of the workflow ends. Use one to show a result while you build, to send the outcome to a chat channel or other webhook, or to tell a supervisor how the run ended.
</Info>

A terminal consumes messages and ends a branch. It has no output ports, so nothing can be wired from it. All three terminals are always part of the server. The default timeout of a terminal is the engine default of 30 seconds idle; it also covers what the terminal does after its last input.

## CONSOLE_TERMINAL

Writes the payload of every message to the server log. It is the quickest way to see a result while you build a workflow.

| Property | Value |
|---|---|
| Options | none |
| Output ports | none |
| Logs | `Consuming message: <payload>` at DEBUG level for every message, and `Consumed <n> message(s)` at INFO when the input ends |

The whole payload is written to the log in full, but only at DEBUG, so a default INFO configuration shows a message count and no payload data. Payloads can carry personal data or secrets, and large payloads make large logs, so do not enable DEBUG for this terminal on a branch that carries sensitive data in production.

```json
{ "nodeId": "end", "type": "CONSOLE_TERMINAL", "config": {} }
```

## NOTIFY_TERMINAL

Sends each message as a JSON webhook notification. The body is compatible with Slack incoming webhooks.

| Option | Type | Default | Meaning |
|---|---|---|---|
| `url` | string | none, required | The webhook address. It must be `https`; `http` is accepted only for `localhost`, `127.x.x.x` and `[::1]` |
| `text` | string | none | A fixed text to send. Without it the terminal sends the payload's `text` field, or, when there is none, the payload turned into a string |
| `timeoutMs` | number | `10000` | Request timeout in milliseconds, positive |
| `failureMode` | `ERROR` or `CONTINUE` | `ERROR` | `ERROR` fails the node on a failed send. `CONTINUE` logs the failure and goes on with later messages |

Output ports: none.

Each message becomes one `POST` with the body `{"text": "..."}`. Messages are sent one at a time, in order, so a slow webhook slows the branch that feeds it. A response that is not 2xx counts as a failure, and so does a redirect: the terminal never follows one.

`url` and `text` are used as written and are not variable-resolved, so a message cannot choose where it is sent. Any `https` host is accepted, including hosts inside your network, so treat the workflow definition as trusted. The webhook address is itself a secret for many services and is returned as written by the workflow APIs.

This node posts a fixed alert text:

```json
{
  "nodeId": "alert",
  "type": "NOTIFY_TERMINAL",
  "config": {
    "url": "https://hooks.slack.com/services/T000/B000/XXXX",
    "text": "Quality gate failed",
    "timeoutMs": 5000,
    "failureMode": "CONTINUE"
  }
}
```

To send text built from the message, put it in a `text` field of the payload first, for example with a `MAPPER` node (see [Transform](/plugins/transform)), and leave the `text` option out.

## OUTCOME_TERMINAL

Names the exit a run took, so a [supervisor](/running/supervisors) can act on it. Put one at the end of each exit of a workflow.

| Option | Meaning |
|---|---|
| `outcome` | Required: `SUCCESS`, `RETRY` (the cause was repaired, run again), `ESCALATE` (needs a fixer) or `FAILED` |
| `restartFrom` | Node to restart from; omit to restart from the start |
| `reason` | Free text for the supervisor |

Output ports: none.

```json
{ "nodeId": "needs-retry", "type": "OUTCOME_TERMINAL", "config": { "outcome": "RETRY", "restartFrom": "tests", "reason": "flaky test" } }
```

Every terminal reports `reached` in the metadata of its `SUCCESS` status event: `true` if a message arrived, `false` for an exit the run did not take. `OUTCOME_TERMINAL` adds `outcome`, `restartFrom` and `reason` to that metadata, and only when it was reached. A rule keys on them, for example `"if": "metadata['reached'] == true and metadata['outcome'] == 'RETRY'"` (see [rule files](/running/rule-files)).

## Limits and defaults

| Item | Value |
|---|---|
| Default node idle timeout | 30 seconds |
| `NOTIFY_TERMINAL` `timeoutMs` | 10000 |
| `NOTIFY_TERMINAL` requests in flight | 1 per node |
| Plain `http` | only to `localhost`, `127.x.x.x` and `[::1]` |
