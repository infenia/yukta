## AI-first, not AI-dependent

Most workflow tools added AI later, as one more step type. Most agent frameworks are built around a model and do little without one. Yukta was designed for AI from the start, and every part of it still works with no model at all.

Pick how much AI a workflow uses, from none to all of it:

| AI's part | What it looks like in Yukta |
|---|---|
| **None** | Scripts, HTTP calls, SQL, files and rules. [Your first workflow](/learn/your-first-workflow) has no AI step. |
| **A step** | A model call, an MCP tool call, or a decision such as classify, gate or score. See [Mix rules and AI](/learn/mix-rules-and-ai). |
| **The worker** | An agent runs as a step: Claude Code, Codex or Antigravity from a preset, or your own agent (one that speaks the Agent Client Protocol, or any terminal program). You watch and steer it. See [Run an agent](/guides/ai/run-an-agent). |
| **The operator** | An assistant connected over MCP writes, starts, watches and fixes workflows, within the role its key allows. See [Let an assistant build a workflow](/learn/let-an-assistant-build-a-workflow). |
| **The supervisor** | A rule set, an AI agent, a workflow or your own program owns runs and decides what may happen next. See [Supervisors](/concepts/supervisors). |

The engine around every step is the same in each row: retries, time limits, failure routes, approvals and an audit record.

## The problems it solves

<Columns cols={2}>
  <Card title="“Done”, with the checks skipped" icon="list-check" href="/concepts/ai-and-deterministic-work">
    An agent told to run the tests can decide it does not need to. In Yukta the process is the workflow, and the engine runs every gate in order, so an agent cannot drop one. Yukta's own builds and checks run this way.
  </Card>
  <Card title="An agent you cannot see or stop" icon="eye" href="/guides/ai/run-an-agent">
    Watch a running agent, send it a message or interrupt it from the Agents tab. Pause, step, set a breakpoint on or stop any run while it goes.
  </Card>
  <Card title="A model run that costs more than planned" icon="coins" href="/guides/ai/set-token-budgets">
    Give a run a shared budget of tokens, cost and tool calls. When it is used up, the whole run ends.
  </Card>
  <Card title="Risky actions decided by a prompt" icon="user-check" href="/concepts/who-decides">
    A run asks a typed question and waits. Questions are routed by risk through supervisors and people, with escalation and votes, and a high-risk one is only ever answered by a person.
  </Card>
  <Card title="Guardrails you cannot try first" icon="clock-rotate-left" href="/guides/supervise/replay-a-supervisor">
    Write a supervisor as rules, a workflow or an agent, then replay it on a past run in dry run to see what it would have done before it touches a live one.
  </Card>
  <Card title="AI-written automation you cannot review" icon="code-compare" href="/guides/build/validate-and-roll-back">
    A workflow is data (JSON), not code. Yukta checks a draft before saving it, names the node at fault, and keeps versions you can compare and roll back.
  </Card>
</Columns>

## Bring your own agents

<Columns cols={2}>
  <Card title="Assistants that drive Yukta" icon="robot" href="/guides/ai/connect-an-assistant">

  <Card title="Agents Yukta runs as steps" icon="play" href="/guides/ai/run-an-agent">

  </Card>
  <Card title="Your own agent as a supervisor" icon="shield-halved" href="/guides/supervise/write-an-agent-supervisor">
    A script, a service or an AI agent reads signals and sends decisions over HTTP, on a credential you can revoke.
  </Card>
  <Card title="The model you choose" icon="brain" href="/guides/ai/call-an-llm">
    Call Anthropic, OpenAI, Ollama or any OpenAI-compatible endpoint from a step, keep its key out of the workflow, and fall back to a second model when a call fails.
  </Card>
</Columns>

People use the web UI, scripts use `yukta-cli` or REST, and assistants use MCP. A run can also start from a webhook or a schedule: its trigger step decides how. Every way in goes through the same checks and leaves the same audit record.


## Run it in three steps

<Steps>
  <Step title="Install">
    On Linux and macOS, one command installs the server (`yukta`) and the client (`yukta-cli`). On Windows, use the `.zip` from the release page; for Docker and other ways, see [Install Yukta](/get-started/install).

    ```bash
    curl -fsSL https://github.com/infenia/yukta/releases/download/v0.1.0-alpha.5/install.sh | sh
    ```
  </Step>
  <Step title="Start the server">
    Run `yukta`, then check it from a second terminal:

    ```bash
    curl http://localhost:9858/actuator/health
    ```

    ```json
    {"groups":["liveness","readiness"],"status":"UP"}
    ```
  </Step>
  <Step title="Open the web UI or connect an assistant">
    Open http://localhost:9858 and follow [Your first workflow](/learn/your-first-workflow). Or connect your assistant once:

    ```bash
    claude mcp add --transport http yukta http://localhost:9858/mcp
    ```

    Then ask it in plain words, for example: *"Build a workflow that checks a new customer's details, drafts a welcome email with a model, and waits for my approval before sending it."* You review each change before it applies. More prompts are in [Configure Yukta by asking](/guides/ai/configure-with-an-assistant).
  </Step>
</Steps>

Prefer to look first? [Try a workflow in your browser](/learn/playground).

## Two editions

| | Community | Plus |
|---|---|---|
| **Licence** | Apache-2.0 | AGPL-3.0-only, or a commercial licence |
| **State** | In memory only. A restart gives a clean server | PostgreSQL keeps definitions, versions, run history, checkpoints and open questions |
| **After a restart** | Apply your workflows again (from a folder at start-up, or with the CLI) | Interrupted runs resume from their checkpoints |
| **Adds** | — | High availability with failover, remote workers |

Start with Community: one binary, no database. Move to Plus when a restart must not cost you a run. See [Persist sessions](/guides/operate/persist-sessions) and [Licensing and editions](/reference/licensing).

## Honest limits

- **Alpha.** The workflow JSON, REST API, MCP tools and plugin contract can change before 1.0. See [Releases](/reference/releases).
- **Young ecosystem.** There are many built-in steps, but far fewer ready-made connectors than older tools.
