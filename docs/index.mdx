## What a workflow looks like

Every workflow is built from three kinds of box, joined by arrows. Here, a job fetches data, tidies it up and sends a notification. If the call fails, the item is set aside for later.

<img className="yk-diagram block dark:hidden" src="/images/diagrams/workflow-anatomy.light.svg" alt="A trigger starts the flow, two processors call an API and transform the result, and terminals end each branch. A failed call goes to a dead-letter terminal." loading="lazy" />
<img className="yk-diagram hidden dark:block" src="/images/diagrams/workflow-anatomy.dark.svg" alt="A trigger starts the flow, two processors call an API and transform the result, and terminals end each branch. A failed call goes to a dead-letter terminal." loading="lazy" />

| Box | What it does | Example |
|---|---|---|
| **Trigger** | Starts the job | A request arrives, a timer fires |
| **Processor** | Does work or makes a choice | Call a web service, reshape data, ask an AI model |
| **Terminal** | Ends a path | Log the result, send a notification, keep a failed item |

The arrows are **edges**: "when this step is done, hand its output to the next." A step can have labelled exits, called **ports**, such as `success` and `error`, so good and bad outcomes take different paths. Each box is a **plugin**, a ready-made capability you configure; you can also write your own.

## Why Yukta

<CardGroup cols={2}>
  <Card title="Workflows are data" icon="diagram-project">
    A JSON graph, not a program. Easy for people, tools and AI assistants to write and review.
  </Card>
  <Card title="Start it from anywhere" icon="plug">
    REST API, web UI, command line or an MCP client such as Claude, all from one definition.
  </Card>
  <Card title="Built for AI agents" icon="robot" href="/building/ai-and-agents">
    Model calls with budgets, approvals and memory around them, plus cheap decision models for routing.
  </Card>
  <Card title="Watch it, steer it, trust it" icon="shield-halved" href="/running/run-controls">
    Pause, retry or stop a live run. Retries, error routes and time limits are built in, and a new server only accepts local connections.
  </Card>
</CardGroup>

<Info>
  **For developers:** Yukta is a reactive, DAG-based workflow orchestration server. The flowchart is a directed acyclic graph, so it can never loop back by accident, and messages stream from step to step with back-pressure.
</Info>

<Note>
  Yukta is pre-beta (`0.1.0-alpha.2`). The workflow JSON, REST API, MCP tools and plugin contract may change before v0.1.0. See [Releases](/reference/releases).
