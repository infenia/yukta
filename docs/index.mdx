## What Yukta does

You know how a job should go: build, test, review, approve, deploy. Written in a wiki, a prompt or a script, the process quietly stops being followed: a check is skipped, an agent decides a step is not needed this time, and nobody can say what state the work is in.

Yukta is a server that keeps the process. You describe the steps as a **workflow**: a flowchart where boxes are steps and arrows say what happens next. Yukta runs it the same way every time, and you keep a hand on the controls while it runs.

## Install

On Linux, one command installs the server (`yukta`) and the client (`yukta-cli`):

```bash
curl -fsSL https://github.com/infenia/yukta/releases/download/v0.1.0-alpha.3/install.sh | sh
```

This one-line installer is for **Linux** (amd64). For Docker, macOS, Windows and other ways to install, see [Install Yukta](/get-started/install).

## Configure it by asking

Connect an AI assistant once, then describe what you want. The assistant writes the workflow, adds the supervisor, assigns it and checks the result, and asks you before anything risky.

```bash
claude mcp add --transport http yukta http://localhost:9858/mcp
```

Then, in your assistant:

> Build a workflow that validates a release ticket, asks a model to draft the notes, and waits for my approval before deploying.

> Add a supervisor that pauses the release when three deploys fail in a row. Start it in dry run.

> Replay that supervisor on yesterday's failed run and show me what it would have done.

Three prompts, no JSON written by hand. You review each change before it applies. Start with [Let an assistant build a workflow](/learn/let-an-assistant-build-a-workflow), then [Set up supervision with an assistant](/learn/set-up-supervision-with-an-assistant). More prompts are in [Configure Yukta by asking](/guides/ai/configure-with-an-assistant).

## Try it in 30 seconds

With Yukta [installed](#install), start the server with `yukta`, then check it is up from a second terminal:

```bash
curl http://localhost:9858/actuator/health
```

```json
{"groups":["liveness","readiness"],"status":"UP"}
```

Next: [install Yukta](/get-started/install), then [run your first workflow](/learn/your-first-workflow). Prefer to look first? [Try a workflow in your browser](/learn/playground).

## Who it is for

- **You run jobs and pipelines** and want every step to happen, in order, with a record. Start with [Your first workflow](/learn/your-first-workflow).
- **You build with AI agents** and want rules, budgets and approvals around them. Start with [Mix rules and AI](/learn/mix-rules-and-ai).
- **You operate it for a team** and need to know who can steer what. Start with [Add a supervisor](/learn/add-a-supervisor) and [Deploy](/guides/operate/deploy).
- **You extend it** with your own step. Start with [Write a plugin](/guides/extend/write-a-plugin).

## Honest limits

Yukta is alpha. The workflow JSON, REST API, MCP tools and plugin contract can change before 1.0. Sessions live in memory by default, and the native server in the current release is Linux amd64 only. See [Releases](/reference/releases) and [What's new in alpha.4](/reference/whats-new-alpha-4).
