You will run a tiny workflow that takes a name and returns a greeting. It shows the loop you will use for every job: **save the flowchart, start a run, read the result.**

<img className="yk-diagram block dark:hidden" src="/images/diagrams/quickstart-greet.light.svg" alt="The quickstart workflow: an API trigger receives a name, a mapper builds a greeting, and a console terminal shows Hello, Ada." loading="lazy" />
<img className="yk-diagram hidden dark:block" src="/images/diagrams/quickstart-greet.dark.svg" alt="The quickstart workflow: an API trigger receives a name, a mapper builds a greeting, and a console terminal shows Hello, Ada." loading="lazy" />

You need a terminal and `curl`. You do not need Java or the source code.

<Note>
  Yukta `0.1.0-alpha.2` ships a native server for Linux (amd64), a Docker image, and the command-line client for Linux, macOS and Windows. On macOS or Windows, run the server with Docker. See [Releases](/reference/releases).
</Note>

## 1. Install and start the server

<Tabs>
  <Tab title="Linux" icon="terminal">
    ```bash
    curl -fsSL https://github.com/infenia/yukta/releases/download/v0.1.0-alpha.2/install.sh | sh
    yukta
    ```

    The script checks file checksums, never uses `sudo`, and installs `yukta` (server) and `yukta-cli` (client) into `/usr/local/bin` as root or `~/.local/bin` otherwise.
  </Tab>
  <Tab title="Docker" icon="docker">
    ```bash
    docker run --rm -p 127.0.0.1:8080:8080 \
      -e YUKTA_API_KEY=change-me \
      ghcr.io/infenia/yukta:0.1.0-alpha.2
    ```

    A container needs an API key. Add `-H "X-API-Key: change-me"` to every `curl` below. The web UI does not send a key yet, so use `curl`, the CLI or MCP with this setup.
  </Tab>
</Tabs>

Check that it is up:

```bash
curl http://localhost:8080/actuator/health
```

```json
{"groups":["liveness","readiness"],"status":"UP"}
```

Prefer packages, archives or building from source? See [Deployment](/operations/deployment).

## 2. Save the workflow

A **session** is a folder of workflows. Save this one as `session.json`, then send it to the server.

```json
{
  "sessionId": "demo",
  "name": "Quickstart",
  "description": "Greet a user",
  "initiator": "me",
  "projectPath": "/tmp",
  "workflows": {
    "greet": {
      "workflowId": "greet",
      "description": "Map the request payload into a greeting",
      "nodes": [
        { "nodeId": "trigger", "type": "API_TRIGGER", "config": {} },
        {
          "nodeId": "map",
          "type": "MAPPER",
          "config": {
            "mode": "PROJECTION",
            "mapping": { "greeting": "'Hello, ' + payload.name" }
          }
        },
        { "nodeId": "end", "type": "CONSOLE_TERMINAL", "config": {} }
      ],
      "edges": [
        { "source": "trigger", "target": "map" },
        { "source": "map", "target": "end" }
      ]
    }
  }
}
```

```bash
curl -X POST http://localhost:8080/api/sessions \
  -H "Content-Type: application/json" -d @session.json
```

Three nodes, one of each kind: the trigger receives your input, the mapper builds the greeting, and the terminal ends the path.

## 3. Start a run

```bash
curl -X POST http://localhost:8080/api/workflow/start \
  -H "Content-Type: application/json" \
  -d '{"sessionId":"demo","workflowId":"greet","payload":{"name":"Ada"}}'
```

The server answers `202 Accepted` with an **execution id** in `data.executionId`, a ticket number for this run. The run continues in the background.

## 4. Read the result

Use the execution id from step 3:

```bash
curl http://localhost:8080/api/executions/{executionId}
curl -H "Accept: application/json" \
  http://localhost:8080/api/sessions/demo/executions/{executionId}/results
```

The first call returns the status, `SUCCESS` once every node has finished. The second returns what reached the terminal:

```json
{ "kind": "RESULT", "nodeId": "end", "payload": { "greeting": "Hello, Ada" } }
```

<Tip>
  Sessions are held in memory, so apply them again after a restart. To follow a run live, use `/api/executions/{executionId}/status/stream` or the logs endpoint.
</Tip>
